1. multimodal-art-projection/YuE:
   star: 8574  语言/技术: Python 3.12, PyTorch（由 .whl 打包与 Hugging Face 权重分发推断）, AR–NAR Mixture-of-Transformers, Flow Matching 生成声学潜变量, VAE 音频解码（48 kHz 立体声）, ABC 记谱法（symbolic score 表示）, Hugging Face Transformers / Hub（模型加载方式）, NVIDIA CUDA + BF16
   项目简介: 一句话概括：YuE2 是一个开源的全曲音乐生成大模型，你给它一段歌词和一个风格提示词，它先写出「旋律+和弦」的乐谱方案，再把这个方案渲染成带人声和伴奏的完整歌曲。它最大的差异化在于「白盒」——不是黑箱吐一段音频，而是先产出一份人类可读、可改的 ABC 乐谱，改完再重新渲染。除了原创歌曲，它还能做零样本翻唱（把一首转录出来的歌换个风格重唱）以及通过对话让 Agent 改和声、改歌词、改编曲。官方宣称在自家 WildSongBench 上跟 Suno v5/v6 打得有来有回，best-of-8 设置下 SongBench 均分 6.9632，是目前评测设置里最高的观测均值。附带还有两个 SOTA 小模型：SheetSage2（音频转乐谱）和 MERT2（音乐理解）。
   亮点: 白盒音乐生成：先生成可读可编辑的旋律+和弦乐谱（ABC 格式），人和 Agent 都能检查、修改，再渲染成完整录音——这是它区别于 Suno 这类黑箱产品最核心的技术壁垒; 前沿音质：在自建 WildSongBench（192 条 prompt）上，YuE2 best-of-8 拿到 6.9632 SongBench Avg，README 声称与 Suno v5/v6 处于同一水平线; 零样本翻唱：用 SheetSage2 把一段原始录音转成旋律乐谱，再用 cot='melody' 模式配新歌词/新风格重新演唱，无需针对翻唱做微调，948 首作品上达到 0.647 CLEWS mAP（无乐谱仅 0.006）; Agent 原生设计：仓库自带 yue2-music skill（SKILL.md），教 Agent 生成歌曲、转录翻唱、编辑 ABC 乐谱、检查音乐不变量，并组织 A/B 试听对比; 完整的阶段性 Python API：plan() → generate_semantic() → synthesize() → decode()，每一步产物（乐谱、语义 token、声学潜变量、生成配置）都落盘可复用
   详细报告: 先把话说白：YuE2 干的是「AI 写歌」这件事，但它走了一条跟市面上大部分音乐生成工具不太一样的路。大多数产品（包括 README 里对比的 Suno、Mureka、MiniMax 等）本质上是「你给提示词，我吐音频」，中间过程是个黑箱，你听到的成品不满意，也只能改提示词再抽卡。YuE2 的卖点是把这个黑箱拆开一层——它先生成一份「旋律 + 和弦」的乐谱方案（用 ABC 记谱法表示），这份乐谱是纯文本、人类可读、可以被编辑的；确认或修改之后，再把它「渲染」成 48 kHz 立体声、带人声和伴奏的完整歌曲。作者管这个叫 white-box music generation，翻译成人话就是「先看图纸，再盖房子，图纸还能改」。

技术架构上，README 给出的关键信息是：一个 AR–NAR 的 Mixture-of-Transformers 骨干网络，自回归地同时预测乐谱 token 和语义音乐 token，然后用 flow matching 生成声学潜变量，最后由 VAE 把这些潜变量解码成立体声音频。创作、翻唱、编辑三种任务的区别只在于「乐谱从哪来」——是模型自己生成的、是从录音转录出来的、还是人为编辑过的。API 被拆成了清晰的阶段：plan() 出乐谱方案，generate_semantic() 出语义 token，synthesize() 出潜变量，decode() 出音频。中间产物全部保存到输出目录，意味着你可以只重跑其中一段，不必每次从头抽卡——这对做 A/B 对比和迭代调参非常友好。

功能上有四种 cot（chain-of-thought 式乐谱规划）模式：cot='full' 生成完整可编辑的旋律+和弦方案（新歌默认）；cot='melody' 只固定旋律、伴奏自由发挥，官方推荐用于翻唱；cot='off' 直接从歌词和风格生成；abc=... 则允许你直接喂一份自己写的乐谱进去。翻唱流程是：先用 SheetSage2（一个音频转乐谱的 SOTA 模型）把原曲转录成旋律 ABC，审一遍，再配上新歌词或新风格去生成——README 特别提示翻唱要用不带和弦符号的乐谱，这样伴奏才能跟着新风格走。编辑流程则是导出 plan、复制 score.abc 改成 edited.abc、让 Agent 改和声/旋律/速度/曲式，再喂回去重新生成一整首录音（注意：它不保留原始波形，属于「重新演绎」而非「局部修音」）。

硬门槛方面要说清楚：Linux、Python 3.12、支持 BF16 的 NVIDIA GPU、24 GB 显存，模型权重首次使用时从 Hugging Face 下载。24 G 显存基本把消费级中端卡挡在门外了（4090 24G 刚够，往下就费劲），这是普通开发者上手前必须掂量的成本。许可证也要划重点：代码、Agent skill 和文档是 Apache 2.0，但模型权重是 CC BY-NC 4.0——也就是非商业用途，想拿去做商业产品得另外谈授权（README 留了合作与授权邮箱）。

配套生态还挺完整：除了主模型 YuE2-3B，还有解码器 YuE2-Vae / YuE2-Vae-legacy（后者是复现 benchmark 用的）、转录模型 SheetSage2、音乐理解模型 MERT-v2-FullSong / MERT-v2-30s（SheetSage2 的编码器）、以及评测集 WildSongBench。README 里宣称 MERT2 在 15 项 MARBLE 指标中拿下 14 项 SOTA、GTZAN 流派分类 91.72%；SheetSage2 在 13 项指标中拿下 10 项 SOTA、RWC-Pop 人声旋律音级 F1 达 82.51%——不过这些数字都是自报的，且 benchmark 也是自建的，需要第三方独立验证，作者自己也承认最高均分之差「不足以确立统计显著性」，这点挺诚实。

2. debpalash/VoiceStudio:
   star: 27380  语言/技术: Python 3.11+, Bun / Node 20+, Tauri（致谢中提及）, Electron（README 提示正在重写中）, Docker（linux/amd64 镜像，含 CUDA/ROCm/CPU/worker-only 配置）, uv（Python 依赖管理）, CUDA, Apple Silicon MPS / MLX, ROCm（Linux）, REST / SSE / WebSocket 本地 API, OpenAI 兼容音频 API, MCP Server, OmniVoice / CosyVoice 3 / GPT-SoVITS / VoxCPM2 / IndexTTS 2.5 / KittenTTS / Sherpa-ONNX / MLX-Audio 等 TTS 引擎, WhisperX / Faster-Whisper / MLX Whisper / Parakeet MLX / Moonshine 等 ASR 引擎, Demucs（人声分离）, Pyannote（说话人分离）, CTranslate2, AudioSeal（音频水印）
   项目简介: 一句话概括：VoiceStudio（前身 OmniVoice-Studio）是一款“跑在自己电脑上”的多功能语音工作台——克隆音色、给视频配音、语音转写听写、做有声书和长音频，全都本地完成。它把 16 个 TTS 引擎和 11 个 ASR 引擎塞进同一个桌面应用（macOS/Windows/Linux/Docker），挂着 646 种语言的目录，不需要账号、API Key、订阅或按量计费。痛点很直白：市面上的语音服务要么把音频上传到别人家服务器，要么按分钟收费，要么不能换成自己想用的模型。VoiceStudio 换了个思路——算力你自己出，软件免费，数据默认不出本机；同时它还开放了本地 REST/SSE/WebSocket、OpenAI 兼容音频接口和 MCP Server，你可以把它当成一个自建的语音基础设施。
   亮点: 16 个 TTS 引擎 + 11 个 ASR 引擎的“可插拔军火库”，通过 Model Catalogue 一键安装/卸载/切换（Ctrl/Cmd+E 呼出引擎面板），默认用 k2-fsa/OmniVoice，覆盖 600+ 语言; 一条龙配音流水线：上传文件或导入 URL → 转写 → 翻译 → 保留说话人 → 合成 → 导出视频，附带波形+时间轴双语对轴编辑、术语表（Glossary）和译后语速/时序校验; 有声书/故事生产：多角色剧本、EPUB/PDF 导入、分章渲染、直接导出 .m4b——把“录有声书”这件事从几个月压缩到几杯咖啡的时间; 系统级听写小工具（Dictation Widget）：全局快捷键唤起、实时转写，还能接本地 LLM 做文本润色; 本地优先 + 隐私默认值：音频、转写、音色、项目默认全部留在本机，遥测默认关闭，开启时也只发白名单内的无内容元数据；另外内置 AudioSeal 不可感知水印，用来给合成语音做“出处标记”; 跨硬件智能调度：CUDA / Apple Silicon MPS / MLX / ROCm / CPU 自动检测与路由，显存不够自动 offload 到 CPU，还支持把模型下载与推理分发到远程 worker; 对外接口丰富：本地 REST/SSE/WebSocket、OpenAI 兼容音频 API、MCP Server——AI Agent 生态可以直接把它的合成与转写当工具调用; 批量队列 + 文件夹监听：一次排大队音频/视频任务，或者盯着某个目录，新视频一出现就自动处理（自动化剪辑/字幕组狂喜）
   详细报告: 先说定位：VoiceStudio 不是又一个“在线配音网站”，而是一个本地优先（local-first）的语音生产车间。它把语音克隆、语音设计、视频配音、听写、有声书、批量生成这几件事收拢到同一个桌面应用里，官方对比表写得很直白——和典型托管式语音服务相比，它用“你自己管硬件”换来了“数据默认不出本机、无订阅按量计费、可离线、模型和路由全开放”。

核心工作流分三块。第一块是 Voice 工作区，有三个标签页：From audio（从一段音频克隆音色，3 秒可用，5–15 秒效果更好）、By design（不靠参考音频，而是用年龄、口音、音高、风格、表达方式等指令“设计”出一个音色）、Convert（语音到语音的音色转换）。第二块是 Dubbing（视频配音）：从文件或 URL 导入，支持字幕导入、可选 YouTube 登录，然后走“转写 → 翻译 → 说话人保持 → 合成 → 导出”的链路；编辑界面把播放控制叠在视频上并做背景虚化，波形和带时间戳的转写合并成一个紧凑编辑面，波形可拖动平移、点击定位；翻译语言与 ISO 代码联动，选 Auto 会清掉之前的语言和方言；转写条目按“可编辑文本 / 时序与状态 / 音色控制”三行分组；还有 Glossary 术语表和时间轴问题标记，方便译后复查。第三块是长音频：Audiobook Script 编辑器、多角色配音脚本、EPUB/PDF 导入、分章渲染、导出 .m4b；casting board 用图标式音色卡片，支持把卡片拖到某个说话人上，或从菜单挑音色。

周边能力也很扎实：Dictation Widget 提供系统级快捷键和实时转写，可选接本地 LLM 做文本清理；Vocal Isolation 用 Demucs 分离人声与背景；Speaker Diarization 用 Pyannote 和 WhisperX 做说话人归属；Batch Queue 支持大批量音视频任务排队、逐任务进度，甚至监听本地目录自动接活。基础设施层是 Model Catalogue（安装、删除、选择、路由 TTS/ASR/LLM 模型）、远程 worker 上的模型下载（带实时进度）、GPU 自动检测与按引擎校验、诊断面板（自检、错误日志、脱敏支持包）。

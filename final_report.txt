它的核心工作流非常直白：你给它一个链接（config.yml 里的 link 列表，或者命令行 -u 追加），它判断链接类型，然后走对应的抓取路径。支持的类型包括：/video/{aweme_id} 单视频、/note/{note_id} 与 /gallery/{note_id} 图文笔记、/collection/{mix_id} 与 /mix/{mix_id} 合集、/music/{music_id} 音乐（优先直链音频，失败则回退到该音乐关联的第一个作品）、v.douyin.com 之类的短链、/user/{sec_uid} 主页批量，以及登录态下的 /user/self?showTab=favorite_collection 收藏夹。作者主页批量还能细分 mode：post（作品）、like（点赞）、mix（合集）、music（音乐），并且支持跨模式 aweme_id 去重，同一条作品不会因为同时开了 post 和 like 被下载两遍。

抓取之后是“工程化的脏活”。并发默认 5，重试默认 3 次，用 1s/2s/5s 的指数退避，请求速率默认压到 2 req/s，尽量别把自己送进风控小黑屋。下载完成会做 Content-Length 校验，对不上就判定不完整并自动清理，避免你半年后发现素材库里有 200 个 0 字节的 mp4。进度用 Rich 进度条展示，嫌吵可以把 progress.quiet_logs 打开，调试时再上 --show-warnings 或 -v。

“增量下载”这块的设计挺有意思，也容易被误解：它其实是**双重判定**——既有 SQLite（dy_downloader.db，表 aweme 记录元数据）又有本地文件扫描。increase.post 等开关为 true 时，只有当当前下载目录下存在非空主媒体文件才跳过；README 明确说明 SQLite 历史记录并不参与“是否跳过”的决策。所以只删数据库不删文件 = 不会重新下载；只删文件不删数据库 = 会重新下载（程序认为“库里有、本地没有”就该补）。要强制重下就得两头清理，文档甚至给了 sqlite3 的 DELETE 语句和一键全量重置的 rm 命令，属于把 FAQ 写进运维手册了。

反爬兜底是另一个重点。文档反复强调一个很现实的坑：“为什么我只能拿到 20 条左右？”——这是常见的分页风控行为。解法是把 browser_fallback.enabled 打开、headless 设为 false，在弹出的浏览器里手动过验证，别手贱提前关窗口。项目还提供 python -m tools.cookie_fetcher --config config.yml 一键自动抓 Cookie，登录后回车即可写回配置，比手动从开发者工具里扒 msToken/ttwid/odin_tt/passport_csrf_token/sid_guard 舒服太多。

   亮点: 一套代码吃下从 2B 到 462B 参数的 Transformer 训练，6,144 张 H100 上实测 462B 模型，MFU 高达 47%，且是端到端（含数据加载、优化器步、通信、日志）口径的诚实数据; 五种并行策略全家桶：TP、PP、DP、EP、CP，外加通信重叠优化（--overlap-grad-reduce、--overlap-param-gather、--tp-comm-overlap），把「通信墙」按在地上摩擦; 混合精度一路从 FP16 卷到 FP4，紧跟硬件代际（文档提到 Blackwell 性能增强），还支持 Muon 等新兴优化器和 Falcon-H1 混合 Transformer-Mamba 架构、BitNet 三值量化; 提供了完整的生产级闭环：预训练脚本 + 检查点转换（Megatron Bridge 双向 HF ↔ Megatron）+ 后训练（量化、蒸馏、剪枝）+ 强化学习（含 RLHF）+ 推理引擎与导出; 动态上下文并行（Dynamic Context Parallelism）为变长序列训练带来最高 1.48x 加速，专治长文本训练时 GPU 空转
   详细报告: 先给这个项目一个接地气的定位：它就是大模型训练界的「重型机械操作手册」。普通开发者用 PyTorch 单卡或几卡 DDP 跑个小模型没问题，但一旦模型大到单张卡连权重都塞不下（比如 175B 的 GPT-3、462B 的巨兽），常规玩法直接原地爆炸——显存不够、通信爆炸、GPU 利用率低到心疼。Megatron-LM 就是 NVIDIA 给出的答卷。

项目拆成两个组件，分工明确。Megatron-LM 是「参考实现 + 预配置训练脚本」，你可以理解为搭好的乐高样板间：科研团队想学分布式训练怎么玩、想做快速实验，直接照着脚本跑就行。Megatron Core 则是拆散的一箱积木：Transformer 构建块、并行策略、混合精度、模型架构，全部可组合，适合框架开发者和 ML 工程师搭自己的训练流水线（文档明确说它面向「custom training frameworks」）。

核心技术壁垒在于并行策略矩阵。TP（张量并行）把单层矩阵乘切到多卡；PP（流水线并行）把不同层切到不同 GPU 形成流水；DP（数据并行）复制模型分数据；EP（专家并行）服务于 MoE 稀疏模型；CP（上下文并行）专治长序列。这五种可以叠加组合，配合细粒度的通信重叠技巧（梯度 reduce 重叠、参数 gather 重叠、TP 通信重叠，PP 通信默认开启），把通信时间藏进计算里。文档给出的性能数据相当硬核：弱扩展下模型越大 MFU 越高（41% 提到 47–48%，因为大 GEMM 算术强度更高、更划算）；强扩展把 175B+ 的 GPT-3 从 96 张 H100 推到 4,608 张，同一批次大小下 MFU 从 47% 掉到 42%，说明「规模越大通信越暴露」这个物理规律没法违抗，只能优化。

精度方面，FP16/BF16/FP8/FP4 全支持，明显是跟着 NVIDIA 硬件代际走的，文档还提到 Blackwell 性能增强的路线图，属于典型的「软硬协同」打法。生态配套也很全：Megatron Bridge 提供 Hugging Face ↔ Megatron 检查点双向转换（这解决了一个大痛点——社区模型权重和训练框架之间不通婚），还有 MoE Model Zoo 给出 DeepSeek-V3、Mixtral、Qwen3 的优化配置，后训练模块负责量化/蒸馏/剪枝，rl 模块做强化学习含 RLHF，inference 模块带推理引擎和 server，export 模块能以 TensorRT-LLM 为示例导出。

安装上支持 uv pip install megatron-core 直接装，也能源码编译（文档温馨提示：编译很吃内存，OOM 就设 MAX_JOBS=4 限制并行编译任务数）。值得注意的兼容性变化：即将到来的 0.17.0 版本会砍掉 Python 3.10 支持，下游应用得把下界抬到 3.12。最新动态里提到 DeepSeek-V4 初步支持、Muon 等新兴优化器通过 Emerging-Optimizers 库接入、TII 贡献的 Falcon-H1 混合 Transformer-Mamba 架构、动态上下文并行等，节奏相当密集。

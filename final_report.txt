4. uber/ADR:
   star: 732  语言/技术: Python, MCP, Anthropic API, OpenAI API, Claude Code, Cursor, Codex, LLM, Agent, 安全检测
   项目简介: ADR 是 Uber 推出的企业级 AI Agent 安全系统，用于保护员工和客户使用的 AI 代理（如 Cursor、Claude Code、Codex）免受提示注入、恶意工具调用等攻击。它提供可观测性、攻击基准、实时检测和预防四大能力，并已部署于 Uber 生产环境，论文被 MLSys 2026 接收。开源版本包含遥测传感器（Sensor）、基准测试套件（ADR-Bench）和双代理检测器（Detector）。
   亮点: 生产级部署：已在 Uber 生产环境实际运行，论文被 MLSys 2026 接收; 四层能力：观察（Observability）、基准（Benchmark）、检测（Detection）、预防（Prevention），预防暂未开源; 支持 7+ 种 AI 编码工具，跨 macOS/Linux/Windows; ADR-Bench 包含 300+ 任务、133 个 MCP 服务器，覆盖 17 种攻击技术; 双 Agent 检测架构：高召回分诊 + 深度 agentic reasoning
   详细报告: ADR 全称 Agentic AI Detection and Response，是一个针对 AI Agent 的企业级安全检测与响应系统。核心痛点是：随着 Cursor、Claude Code、Codex 等 AI 编程助手以及客户支持型 Agent 的普及，恶意攻击者可以通过提示注入、恶意 MCP 服务器、工具滥用等方式操纵 Agent，造成数据泄露或未授权操作。传统安全工具无法感知 Agent 的意图和行为，ADR 通过四大能力弥补这一空白。

项目首先构建了可观测性（Observability）模块，即 ADR Sensor。它能够跨 macOS、Linux、Windows 平台，从 7 种以上 AI 编码工具（如 Claude Code、Cursor、Codex）以及内部自动化脚本和客户支持 Agent 中，采集 Agent 的意图、工具调用参数和执行轨迹，并标准化为统一 schema。这解决了'黑盒'问题，让安全团队能看到 Agent 在做什么、为何这么做。

其次是基准测试（Benchmark）模块，即 ADR-Bench。它包含 300 多个任务、133 个 MCP 服务器，覆盖全部 17 种 Agent 攻击技术（如提示注入、权限提升、数据外传等）。任务环境是合成的（使用假凭证、模拟环境），用于评估检测器的安全性能，也可用于开发者测试自己的安全方案。

第三是检测（Detection）模块，采用双 Agent（dual-agent）架构：第一层是高召回率的快速分类器，对大量会话进行初步筛选；第二层对可疑会话进行深度的 agentic reasoning（让 LLM 扮演检测者，模拟攻击者思路）。这种两层结构在保证效率的同时提高了检测准确率。项目提供了多种基线检测器（如 llamafirewall）供对比，并支持通过环境变量配置 Anthropic 和 OpenAI API。

第四是预防（Prevention）模块，用于阻止不安全行为，但该模块并未包含在当前开源发布中，作者表示'Stay tuned'，说明是商业版或内部版的一部分。

除了核心代码，项目还提供了完整的可复现实验流程（docs/REPRODUCIBILITY.md），可以用 uv 一键同步依赖，运行检测流水线并生成论文图表。项目采用 Apache 2.0 许可，其中 benchmark/agentdojo 部分是第三方 MIT 代码。

总结来说，ADR 为 AI Agent 安全领域提供了一个工业级的开源参考实现：统一遥测、攻击模拟、高效检测。对于有 AI Agent 使用场景的企业，是评估和强化自身安全能力的重要工具。

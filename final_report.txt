3. cactus-compute/needle:
   star: 6085  语言/技术: Python, JAX, LoRA, Pydantic, Cactus Quants, Simple Attention Network, Walsh-Hadamard Transform, Sinkhorn Iteration, GQA Attention, Byte-level Grammar, Hugging Face
   项目简介: 这是一个仅45M参数、14MB大小的极简语言模型，专为工具调用、设备控制和结构化数据提取而设计，能在超低内存（28MB）下运行，并支持LoRA微调与一键导出。
   亮点: 极简体积：14MB二进制文件、28MB内存即可运行完整会话; 结构化输出：工具调用和提取统一为JSON，字节级语法约束保证格式; 置信度门控：每个响应带置信度分数，可设定阈值实现人机协同; 内置工具检索：从大目录中动态选择top5工具，避免上下文膨胀; 有界内存：256-token滑动窗口+KV sinks，内存占用恒定; 支持LoRA微调并导出单一.cact文件，无需重新编译
   详细报告: Needle 2 是一个专为极端边缘场景打造的 AI 模型，参数仅 4500 万，体积压缩到 14MB，内存占用 28MB，但能力却能和 270M 甚至更大的模型一较高下。它不像传统大模型那样需要 GPU 集群，在普通 CPU 上就能跑，甚至可以塞进手机、路由器或者树莓派。它主要解决两大问题：一是让设备具备'看懂并调用工具'的能力，比如你说'今天要不要带伞？'，它能先调用天气API，再根据结果回答；二是从非结构化文本中提取结构化数据，比如自动识别发票的金额和日期。为了在这么小的体积下保持高质量输出，它内部用了很多黑科技：Hadamard MLP替代传统FFN、GQA注意力、engram记忆，以及一种叫 Cactus Quants 的量化方法，把权重压到 2-bit。同时，它使用字节级语法约束，在生成每个 token 时都强制符合你声明的 JSON schema，所以输出永远是干净的机器可读格式。最贴心的是，它每个响应都带有一个置信度分数，你可以把阈值设为 0.9，低于这个值的就转人工或走保底流程，这样就避免了 AI 瞎编乱造。另外，为了让模型在长对话中不丢记忆，它用了一个 256 token 的滑动窗口，并把工具定义钉在内存里，所以跑多久内存都固定。如果你想定制，它支持 LoRA 微调，你可以用自己业务的工具和示例数据来训练，然后导出成一个 .cact 文件，这个文件直接给同一引擎加载，连编译都不用。整体来看，如果你正发愁怎么把大模型塞进资源受限的设备，或者想让本地程序自动调用复杂 API，这个项目绝对值得研究。不过毕竟是个新项目，GitHub 上还没有什么 stars 和 issues，文档也可能还在完善中，建议实际测试后再上生产。

4. HKUDS/CLI-Anything:
   star: 47636  语言/技术: Python, Node.js, YAML, JSON, Bash, CLI, MCP, REST API
   项目简介: CLI-Anything 是一个让所有软件对 AI 智能体「原生可用」的开源项目，通过自动生成命令行接口（CLI）和技能描述（SKILL.md），使 AI 能够像人类一样操作各种软件，并提供了 CLI-Hub 包管理器来分发和安装这些 CLI。
   亮点: 自动生成 AI 原生 CLI：通过 7 阶段流水线，为任何有代码库的软件生成结构化命令行接口，让 AI 轻松调用。; CLI-Hub 包管理器：提供统一命令 `cli-hub install <name>`，可浏览、安装、更新和卸载社区贡献的 CLI，极大降低了使用门槛。; 多智能体平台支持：与 Claude Code、OpenClaw、Codex 等主流 AI 编程代理深度集成，并支持 SKILL.md 技能发现，让 AI 自主寻找并使用合适工具。; 丰富的生态与验证：已内置 18 个专业软件 demo（如 Blender、GIMP、Zotero 等），并有超过 2280 个测试用例保障质量。
   详细报告: CLI-Anything 是一个旨在消除 AI 智能体与现有软件之间鸿沟的前沿项目，由香港大学数据科学实验室（HKUDS）发起。其核心理念是：既然 CLI（命令行界面）是结构化、轻量、自描述的通用接口，那么将所有软件都封装成 CLI，就能让 AI 用最自然的方式操作它们。

项目提供了一套完整的 7 阶段方法论（HARNESS.md），能够指导 AI 代理分析目标软件的源代码，自动生成对应的 CLI 封装。这个流水线从理解软件功能开始，到设计命令结构、实现、测试、生成文档，最终产出一个可直接安装的 Python 包和一份 SKILL.md 文件。SKILL.md 是 AI 可读的技能描述，使得支持 SKILL 协议的智能体（如 Claude Code、OpenClaw）能够自主发现并正确调用这些 CLI。

除了生成工具，项目还推出了 CLI-Hub 包管理器（pip install cli-anything-hub），用户可以通过 cli-hub 命令浏览、搜索、安装、更新和卸载各种 CLI，包括社区贡献的和公共第三方 CLI。CLI-Hub 不仅支持 pip，还兼容 npm、brew 等多种安装源，并提供了 Web 前端方便用户浏览。

目前，社区已为大量专业软件贡献了 CLI，涵盖 CAD（FreeCAD）、GIS（QGIS）、音视频编辑（Kdenlive、Shotcut）、知识管理（Zotero、Obsidian）、游戏引擎（Godot）等，并附带了详细的测试用例和文档。项目还发布了 arXiv 技术报告，采用 Apache 2.0 许可证。

不过，生成流程严重依赖前沿级大模型（如 Claude Opus 4.6、GPT-5.4），较弱模型可能无法生成高质量 CLI；同时需要访问目标软件的源代码，对于闭源软件效果不佳。此外，生成后往往需要多轮 refine 才能达到生产级质量。

4. multimodal-art-projection/YuE:
   star: 7381  语言/技术: Python 3.12, PyTorch（隐含，文档未明说但为深度学习模型）, AR–NAR Mixture-of-Transformers 骨干网络, Flow Matching（声学 latent 生成）, VAE（latent 解码为立体声音频）, ABC 记谱法（符号乐谱表示）, BF16 混合精度推理, CUDA / NVIDIA GPU, Hugging Face Hub（模型分发）, SKILL.md Agent 技能包规范, MERT2（音乐理解表征编码器）, SheetSage2（音频转乐谱）
   项目简介: 一句话概括：YuE2 是一个开源的全曲音乐生成大模型（3B 参数），你给它一段歌词加一个风格提示，它先写出一份可读、可播放、可编辑的“乐曲总谱”（旋律+和弦的 ABC 记谱），再把这份谱子渲染成 48kHz 立体声、带人声和伴奏的完整歌曲。它最大的痛点是解决了传统 AI 音乐生成“黑盒不可控”问题——过去你只能反复抽卡式地改 prompt，而 YuE2 把音乐变成白盒：人和 Agent 都能先看谱子、改和弦、改曲式、改歌词，再重新渲染，还能零样本翻唱（Cover）已有录音。按论文里的 WildSongBench 基准，它的 best-of-8 配置拿到 6.9632 平均分，宣称可对标 Suno v5/v6。
   亮点: 白盒式音乐生成：先生成可编辑的旋律+和弦规划（ABC 乐谱），再渲染成音频，人可以直接改谱子改风格，而不是黑盒抽卡; 统一了创建 / 翻唱 / 编辑三种任务：同一个 checkpoint，区别只在于乐谱来自模型、来自转录音频、还是来自人手编辑; 零样本翻唱能力突出：在 948 首作品上 full-score 配置达到 0.647 CLEWS mAP，而无乐谱条件仅 0.006，说明符号规划是翻唱保真度的关键; 自带 Agent 技能（skills/yue2-music/SKILL.md），让 AI Agent 能自主完成写歌、转录、翻唱、改 ABC 谱、校验音乐不变量、组织听觉对比; 配套发布 MERT2（音乐理解，15 项 MARBLE 指标中 14 项 SOTA，GTZAN 流派准确率 91.72%）和 SheetSage2（音频转谱，13 项指标中 10 项 SOTA，RWC-Pop 人声旋律音级 F1 达 82.51%）; 输出全程可追溯：产物目录里保留乐谱、semantic tokens、acoustic latents、生成参数和模型标识
   详细报告: YuE2 是 MAP（Multimodal Art Projection）团队推出的第二代开源音乐生成基础模型，核心卖点是两个词：前沿质量 + 可编辑作曲。

先说它解决的痛点。目前主流的 AI 音乐工具（Suno、Mureka、MiniMax Music 等）本质是“歌词+风格提示 → 波形”的黑盒映射。你想改一个和弦、换一个曲式、把副歌提前两小节，唯一的手段就是改 prompt 然后重新抽卡，改完之后整首歌的所有细节都会变，你没法精确定位问题。对于专业音乐人来说这几乎不可用，因为你无法“指挥”它。YuE2 的思路是把生成过程拆成两级：先做符号层的作曲规划（melody-and-chord plan，用 ABC 记谱法表示），再做声学层的渲染。中间那层乐谱是白盒接口——人和 Agent 都能读、能播、能改。改完之后重新渲染，得到一首新的完整录音。README 明确说了：编辑会生成新的完整录音，不会保留原波形（除了编辑本身的那一小段），这点很重要，别指望它做成 DAW 里的非破坏性编辑。

再说技术架构。README 给的描述是：一个 AR–NAR Mixture-of-Transformers 骨干网络，自回归地预测乐谱和 semantic tokens，然后用 flow matching 生成 acoustic latents，最后用 VAE 把 latents 解码成 48kHz 立体声音频（无量化）。这里“AR–NAR”说明它不是纯粹的逐 token 自回归，而是自回归与掩码/非自回归建模的混合专家式 Transformer——这种设计在音乐这种既要长程结构（曲式、段落重复）又要局部细节的任务上比较常见。flow matching 做声学 latent 生成属于当前 TTS/音频生成的主流路线之一（比传统扩散采样步数少、质量高）。三步式的 Python API 暴露得很清晰：plan() → generate_semantic() → synthesize() → decode()，这个分层设计对二次开发非常友好，你可以在任意一层插入自己的逻辑，比如自己写个 plan、自己替换 decoder。

关于“怎么用”，它提供三种 cot 模式：cot="full" 生成完整的旋律+和弦规划（新歌默认）；cot="melody" 只给旋律规划、伴奏自由发挥（官方推荐用于翻唱）；cot="off" 直接用歌词和风格生成。另外 `abc=...` 允许你自己喂一份乐谱（full 或 melody 模式）。这个参数矩阵基本覆盖了“创作、翻唱、编辑”三大场景。

翻唱流程值得单独说：先用 SheetSage2 把源录音转成旋律 ABC，人工（或 Agent）审一遍曲谱，然后配上新歌词或目标风格，用 cot="melody" 且不带和弦符号的谱子，让伴奏适配新风格。这里零样本能力是关键——它用的是通用生成器，没有为翻唱做专门的微调，但 full-score 条件下 CLEWS mAP 从 0.006 飙到 0.647，说明“符号条件”这件事本身就是巨大的信息杠杆。

编辑流程则是：pipe.plan(**request) 导出 plan，里面有个 score.abc，复制出来改成 edited.abc，让 Agent 改它的和声、旋律、速度或曲式，再用 --abc-file edited.abc --cot full 重新渲染。这就形成了一个“音乐版 Git diff + 重新构建”的工作流。

Agent 技能这块是这个项目很有意思的一步棋。它提供了一个 skills/yue2-music/SKILL.md，教 Agent 怎么生成歌曲、转录翻唱、编辑 ABC 谱、检查音乐不变量（musical invariants，比如旋律是否还保持、歌词顺序是否没乱）、组织多个版本的听觉对比。README 里那个示例请求特别典型：“做一版英文钢琴流行，保留原音频和乐谱；再做一版爵士和声，保持人声旋律和歌词顺序，把两版给我对比。”这基本上是把 AI 音乐制作从“单轮生成”推向“多轮迭代的对话式制作”。官方 demo 里那首 The Last Train 走了 9 步、14 个版本，从华语流行改到英文爵士、换和声、加萨克斯 solo，每一版都能听、都能看它的对话记录、乐谱、prompt 和歌词。

性能方面，README 给了 WildSongBench（192 条 prompt，自动评测，日期标的是 2026 年 9 月 12 日）的完整 17 个系统对比表。YuE2 best-of-8 的 SongBench Avg 是 6.9632 排第一，标准 YuE2（从两个候选里挑）是 6.7316，Suno v5 是 6.8721，Mureka 9 是 6.9377，Suno v6 只有 6.5562。AudioBox PQ 上 YuE2 系列（8.27/8.26）也很靠前，但 LeVo 2 的 8.3966 更高；MuLan 上 Suno v5 的 0.5428 最高，YuE2 best-of-8 是 0.5051；PER（音素错误率）上 Suno v4.5 的 5.80% 最低，YuE2 best-of-8 是 9.79%——也就是说它的“唱清楚歌词”能力不是最强的。有意思的是 YuE 1 在这一代基准上只有 4.9165，说明二代是大幅跃迁。README 自己也很诚实地写了：“排名因指标而异；最高均值之间的微小差距不构成统计显著性。”这个态度值得点赞。注意 best-of-8 用了 8 倍算力，标准 YuE2 只挑 2 个候选，横向比的时候得看清配置。

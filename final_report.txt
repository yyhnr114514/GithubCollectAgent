先说 Agent 层。每个 Agent 对应一个具体岗位的日常：Pitch Agent 帮你从可比公司、先例交易、LBO 一路走到带品牌的 pitch deck；Meeting Prep Agent 在每次客户会前准备好简报包；Market Researcher 把某个行业或主题变成行业概览、竞争格局、同业估值和想法清单；Earnings Reviewer 把财报电话会 + 申报文件变成模型更新 + 研报草稿；Model Builder 直接在 Excel 里搭 DCF、LBO、三表模型和可比公司；Valuation Reviewer 吃 GP 包、跑估值模板、起草 LP 报告；GL Reconciler 找账目差异、追根因、走签核流程；Month-End Closer 管应计、结转、差异说明；Statement Auditor 在 LP 对账单发出前做审计；KYC Screener 解析开户文档、跑规则引擎、标出缺漏。注意每个 Agent 插件是自包含的——它把自己需要的技能打包进去，装一个 Agent 就等于装好了它的全部弹药。

再说 Skill/Command 层。README 里把核心的 financial-analysis 和各垂直方向列得很细，比如 /comps（可比公司分析）、/dcf（含 WACC 与敏感性分析）、/lbo、/3-statement-model、/debug-model（Excel 模型审计：公式追踪、硬编码检测、勾稽检查）、/comps、/earnings、/initiate、/ic-memo、/returns（IRR/MOIC 敏感性表）、/unit-economics（ARR cohort、LTV/CAC、净留存）、/kyc 相关规则网格等。这些技能是一次性写在 vertical 里的源，再由脚本同步到各 Agent 的 skills 目录，避免复制粘贴导致版本漂移——这点对多 Agent 仓库来说是很实在的工程考量。

技术实现层面，整个仓库“一切皆文件”：markdown 和 JSON/YAML，没有编译步骤，所以改起来门槛极低。部署路径有两条：一是 Claude Cowork 里 Settings → Plugins → Add plugin，粘贴仓库 URL 或上传 plugins/ 下任意目录的 zip；二是在 Claude Code 里用 claude plugin marketplace add / claude plugin install 装插件。要走无头/服务化部署的，就设置 ANTHROPIC_API_KEY 然后跑 scripts/deploy-managed-agent.sh <agent>，脚本会解析文件引用、上传技能、创建叶子 worker 子代理、把编排器 POST 到 /v1/agents；scripts/orchestrate.py 给了一个参考事件循环，负责在 Agent 之间路由 handoff_request 事件。注意 README 中说明子代理委派（callable_agents）仍是 Research Preview 能力。

   项目简介: Browser Harness 是 Browser Use 团队开源的「AI 代理直连真实浏览器」框架。它通过一条可编辑的 CDP（Chrome DevTools Protocol）WebSocket 把大语言模型直接接到你正在用的浏览器上，让 Agent 能操作你已登录的账号、查看你的真实页面、上传下载文件。最骚的一点是：当 Agent 干活时发现某个 helper 函数不存在，它会自己去写一个塞进本地工作区，下次直接复用——也就是说这个工具会「越用越顺手」，相当于给打工人配了个会自己造工具的程序员救星。安装用 uv + Python 3.12，并提供了 Skill 注册机制和 MCP server，让 Claude Code / Codex / Cursor 等客户端零改造地驱动浏览器。
   亮点: 一条可编辑的 CDP WebSocket 直连真实浏览器，复用你已登录的会话，免去重复登录和 Cookie 搬运的痛点。; Agent 在工作过程中可自行编写缺失的 helper 并保存到 agent-workspace/agent_helpers.py，形成「随任务自进化」的能力累积，而 src/browser_harness/ 保持受保护不被乱改。; 提供 browser-harness-mcp，把浏览器控制 helper 以 MCP tools 形式通过 stdio 暴露，任何 MCP 客户端都能直接驱动浏览器，无需再写第二套 CDP 层。; 支持 Browser Use Cloud 横向扩展（并行多浏览器、实时预览、代理、隐身、验证码识别等），本地做个人化登录任务、云端做大并发任务。; 通过 skill 注册机制 + install.md / SKILL.md 文档教学，让编码 Agent 能自助完成安装与连接。
   详细报告: 这个项目本质上是在解决一个非常现实的痛点：现有浏览器自动化方案（比如拿 Playwright/Puppeteer 从零开一个干净的浏览器）在登录态、验证码、风控面前经常当场去世。Browser Harness 换了个思路——不新开浏览器，直接连你本机那个「已经被你养熟」的真实 Chrome。它靠的是一条可编辑的 CDP WebSocket 通道，Agent 通过 CDP 就能操控标签页、点击、输入、上传文件、抓取内容，天然继承你的登录状态和 Cookie。

它的第二个核心设计是「会自己补工具」。README 里给了一个生动的流程示意：Agent 想上传文件 → 发现 agent_helpers.py 里没有对应 helper → 它自己写一个 → 文件成功上传。这套机制意味着项目本身只提供最基础的底座（src/browser_harness/ 目录被刻意保护起来，防止 Agent 乱改核心），而具体领域能力由 Agent 在本地工作区里现场生长。作者把这一思想称为「Agent Harness 的苦涩教训」——不要在框架里预先塞满所有工具，而是让模型在真实任务中自己长出需要的工具，harness 随着每个任务变得更强。

从工程角度看，它由几块组成：install.md 负责把 Agent 连到浏览器；SKILL.md 教会 Agent 浏览器工作流；src/browser_harness/ 是受保护的核心；agent-workspace/ 是 Agent 自留地；browser-harness-mcp 则把 helper 包装成 MCP tools，经 stdio 暴露给 Claude Code、Devin、Cursor 等 MCP 客户端。安装方式上，README 给出了一段可直接粘贴到 Claude Code 或 Codex 的 setup prompt，要求用 uv + Python 3.12 安装最新稳定版、执行 `browser-harness skill` 注册技能、连接浏览器，并询问是否开启本地浏览器录制（默认否，且升级时保留用户偏好）。连接时需要 Agent 打开 `chrome://inspect/#remote-debugging` 并勾选远程调试选项。

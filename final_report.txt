   项目简介: book-to-skill 是一个将技术书籍、文档文件夹或资料集合转化为统一 Agent Skill 的开源工具，让你可以在 GitHub Copilot CLI、Amp 或 Claude Code 中按需加载书籍章节，以极低的 token 成本获取精准答案，彻底告别“读完就忘”和“PDF 翻页找内容”的痛点。

   详细报告: book-to-skill 是一个用 Python 编写的开源命令行工具，核心解决的是“知识遗忘”和“上下文爆炸”双重痛点。开发者经常购买技术书、阅读文档，但真正使用时却难以快速定位到特定知识点；而如果直接将整本书塞给 AI Agent，不仅 token 成本高得吓人，还容易导致模型“迷失”在长文本中，产生幻觉。

该工具的工作流程分为三步：第一步，用户指定一个文件、文件夹或 glob 模式（如 ./my-book.pdf）；第二步，工具会先提取并清洗原始文本，然后基于一份 SKILL.md 规范（Agent Skills 标准）将内容蒸馏为结构化的技能包——包括核心心智模型、章节索引、词汇表、模式总结和速查表；第三步，生成的技能包被安装到 AI 助手的技能目录中，当用户输入 `/your-book-slug replication` 这样的命令时，Agent 会按需加载对应的章节文件，从真实内容中回答，而不是胡编乱造。

在技术实现上，工具分为两个部分：确定性提取器（document → 纯文本 + 元数据）和规范驱动的生成器（Agent 按 SKILL.md 指导将提取内容转化为结构化技能）。提取器采用模块化设计，针对不同格式适配不同工具链：PDF 方面，对于文本密集型书籍优先使用 pdftotext（poppler），若不可用则回退到 pypdf 或 pdfminer.six；对于包含代码、表格和公式的技术类书籍，推荐使用 docling（约 1.5 秒/页），能保留 Markdown 表格和代码块。EPUB 使用 ebooklib + beautifulsoup4，或内置 zipfile 兜底；DOCX 用 python-docx；HTML 用 beautifulsoup4；RTF 用 striprtf；MOBI/AZW 系列则依赖 Calibre 的 e-book-convert 转换。纯文本、Markdown、reStructuredText 和 AsciiDoc 则无需任何额外依赖。为了简化环境配置，工具还提供了 `python3 scripts/extract.py --check` 命令，可以一键检测各格式提取器的安装状态并给出安装指令。

生成的技能包包含 5 类文件：`SKILL.md`（约 4000 tokens，核心模型 + 章节索引）、`chapters/ch01-*.md`（每章约 1000 tokens，按需加载）、`glossary.md`（约 1500 tokens，术语表）、`patterns.md`（约 2000 tokens，所有技术、算法、设计模式）、`cheatsheet.md`（约 1000 tokens，决策表和速查规则）。其中章节文件是懒加载的，只有用户询问相关主题时才会被计入上下文，因此单次查询的 token 开销极低。根据项目提供的性能数据，相比直接把整本书丢进上下文，这种方法在真实书籍上可减少 24×–51× 的 token 消耗。

除了技术书籍，该工具同样适用于各类结构化知识文档，比如内部技术文档（架构决策记录、运维手册、入职指南）、品牌与设计规范、研究论文集合、RFC 和 API 合同等。凡是需要反复查询的内容，都可以转化为 Agent 技能。项目强调隐私和版权：所有处理都在本地进行，不上传用户文件；生成的技能是高度概括和结构化的衍生内容，不复制原文段落；同时要求用户使用自己拥有合法权属的文档，且不鼓励重新分发受版权保护的衍生物。

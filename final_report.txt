   项目简介: Humanizer 是一个专治“AI味”的文本润色技能。它通过识别 25 种典型的 AI 写作模式（从“不是 X 而是 Y”的舞台式铺垫到空泛的“专家指出”），把机械、刻板、爱说教的人工智能文本，重写成自然、具体、有作者个人风格的真实人类表达，同时严格保证不虚构任何事实。它既可以直接处理粘贴的文本，也能对指定文件里的散文部分进行修改，适用于 Claude Code、Claude Desktop 等支持 Agent Skills 的环境。
   亮点: 识别 25 种 AI 典型写作模式，按强度和频率编号，强力模式单次出现即可触发修改，弱模式则需多处呼应。; 不编造事实：原文缺少的关键细节（如姓名、日期、引文）会向用户提问，而不是脑补。; 支持“声音匹配”：提供你个人的写作片段，Humanizer 会模仿你的用词、节奏、标点甚至破折号习惯。; 三种输出形态：展示第一版重写、对残留人工智能味的点卯、以及最终精修版，全程可监督。; 支持文本、文件语句级修改；只动散文，不碰代码、数据、frontmatter 和链接目标。
   详细报告: Humanizer 是一个“人味修复师”，确切地说，它是一个打包成 Agent Skill 的精细提示词工程。它的目标不是简单地把 AI 文本“换个说法”，而是把 AI 语言模型那种“默认选择最安全、最普适表达”的生成特性，纠正为“针对一个读者、一个主题”的人类选择。

项目本身几乎不包含传统编程代码，核心是一个高度结构化的 SKILL.md 文件，用 Markdown 写成。它完美兼容 Anthropic 的 Agent Skills 体系，你可以用 `npx skills add blader/humanizer --global` 全局安装，也可以通过 Claude Code 的 `/plugin marketplace add blader/humanizer` 来安装插件，甚至手动下载 ZIP 塞进 Claude Desktop 的技能文件夹。这种“只要是 Markdown 就能跑”的极简设计，保证了它能在多个 Agent 平台间无缝迁移。

最核心的武器是 25 种“AI tell”模式，它们来源于维基百科《Signs of AI writing》条目，并被作者重新分类成五大类：

- A 类：**用舞台架势代替正面陈述**。比如“不是 X，而是 Y”这种欲扬先抑的套路、“这就是真正的胜利”这种一言蔽之的收尾、“让我们深入探讨”这种跑酷式过渡，以及“真正重要的是...”这类装深沉的格言。
- B 类：**按既定节奏硬排**。比如硬凑三个排比 (“创新、灵感、洞见”)、一连串相同开头的句子、滥用破折号作为万能连接符、叠加的限定词（“可能也许大概”），以及不必要的连字符短语。
- C 类：**假装权威与拔高意义**。典型词有 delve、testament、landscape；“标志着决定性时刻”、“尽管困难但依然蓬勃发展”这类空转的评语；还有“专家认为”、“曾刊登于纽约时报”这种未经证实的背书。
- D 类：**依模板格式化**。为装饰而加粗关键词、标题加 emoji/箭头、把直引号改成弯引号，这些“合规操作”反而暴露了机器味。
- E 类：**对话残留与草稿指纹**。比如“好问题！希望这对你有帮助”、“根据现有资料无法确认”，甚至“这一函数原先是为了替代...”，这些明显是 AI 聊天时留下的安全毯。

工作流程也很有章法：Humanizer 先对文本中所有可疑模式进行扫描，并按强度排序；然后它不把原文章结构视为金科玉律，大刀阔斧地起一份全新改写稿；再反向校验草稿是否还有残留模式、原意是否被篡改；最后才给出终稿。如果句子缺失一个具体细节（例如“去年十月去的”），它会直接向你提问，绝不会编造一个日期。

这套设计方案带来了很实用的体验：粘贴文本时，你会看到它的“思考过程”——首版改写、对仍显生硬的细节的犀利吐槽、最终润色。而当你给出文件路径时，它只修改正文中的散文部分，完全避开代码块、YAML frontmatter 和超链接。它还能通过你附上的写作样本学习个人语调，因此你看到的终稿不像“AI 装人”，更像“另一个你在写”。

从 1.0.0 到 3.0.0，项目经历过几次大重构。3.0.0 版本把过去 35 个模式归纳为 25 个，统一了“为什么 AI 会写出这种话”的解释框架，加入了更为精细的误判防护（例如“故意使用破折号”也能被尊重）。这种对细节的钻牛角程度，在同类型项目里相当罕见。

当然，它也有明显的边界：目前主要针对英文文本，模式清单基于英文写作习惯，中文的“八百标兵奔北坡”之类的 AI 腔调尚未被覆盖；它没有自带的模型推理能力，必须依附于 Claude 等支持 Agent Skills 的 LLM；由于不是传统代码库，目前也缺少可编程 API。不过，就“如何让 AI 文字像人话”这一课题而言，这个项目提供了教科书级的分解方法，值得每一位做文本生成、Agent 开发的工程师认真研读。

4. **Execution Agent（执行智能体）**：负责生成实际订单和上链执行。它调用Jupiter等交易接口，把风控批准的交易落地，然后输出结构化结果。

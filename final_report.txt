3. cactus-compute/needle:
   star: 11680  语言/技术: Python, Simple Attention Network, Laddered Simple Attention Network, Monarch Hadamard MLP, GQA（Grouped Query Attention）+ causal conv taps, Engram n-gram memory（gather 读取）, Multi-lane hyper-connections, Byte-level grammar 约束解码, Calibrated confidence head（置信度头）, LoRA 微调 / safetensors, Cactus Quants（2.125 bits per weight）, Tensor 序列化格式 .cact, Hugging Face 权重分发, C API / CLI runner / WASI / 浏览器（WASM）, pytest 风格？(未提及)
   项目简介: 一句话概括：Needle 是 Cactus Compute 打造的一个「打工人微型 AI 特工」——一个只有 8-29 MB 的端侧基础模型，专门跑在手机、手表、机器人、智能家居、车机和单片机上。它主动放弃了「陪你聊天」这个虚的 KPI，把所有算力都砸在两件硬活上：一是 Tool Calls（你告诉它 App 有哪些函数，它从用户的一句人话里挑出正确的函数并把每个参数填好），二是 Structured Extraction（你声明一个数据结构，它把一坨乱七八糟的文本变成带类型的字段，比如发票、订单、通知、表单）。顺带还能做文本嵌入，让 App 在本地就能完成搜索、匹配和路由。它的卖点不是「我比 GPT 大」，而是「我比大我 10 倍的模型更会调工具，还塞得进一块几 MB 的固件里」——真正的程序员救星 / 嵌入式打工人神器。
   亮点: 一模型三用：工具调用（Tool Calls）+ 结构化抽取（Structured Extraction）+ 文本嵌入（Text Embedding），一个 8-29 MB 的二进制全包了; 拒绝幻觉的「老实人」设计：问它工具覆盖不到的事，返回空列表而不是瞎猜；每轮回答都带一个经过校准的 confidence 分数，方便你做「执行 / 确认 / 拒绝」的路由决策; 语法约束保证输出可解析：用从你的 schema 编译出来的 byte-level grammar 约束每一个 token，抽取输出保证 parse 得出来，不会给你半个 JSON; 阶梯式（Ladder）架构：一条模型从 2 层到 20 层，每一层深度都是一个可独立部署的模型；参数大头放在 engram 里，所以 121M 的模型能做出 50M 的算术量，还能按设备算力挑深度; 微调后小模型掀桌子：在 DroidCall 上微调让每个子网络提升 18-36 分，从 4 层往上、29M 参数起就能超过 DeepSeek V4 Flash; 一键多平台部署：每个平台目录自带 <1 MB 的预编译引擎，needle build --platform xxx 就把引擎和权重一起打包好，Mac、Linux ARM、浏览器、WASI 全覆盖
   详细报告: 先说说这项目到底是个啥。现在做端侧 AI 的团队普遍有两个痛点：要么把云端大模型硬塞进手机，延迟高、要联网、还费电；要么用一个小模型，结果它只会「嗯嗯啊啊」聊天，真让它干正事（比如帮我订个位、把这封邮件里的信息抠出来）就开始满嘴跑火车。Needle 的定位就是「我不聊天，我干活」。它的目标设备写得很直白：手机、可穿戴、机器人、智能家居、车机、单片机——注意最后那个，单片机都能跑，这意味它对内存和算力的假设是非常苛刻的。

它的核心能力有三条。第一条是 Tool Calls：你用 Python 装饰器 @needle.tool 声明一个函数，函数签名给出参数类型，docstring 就是工具描述，然后 agent.run('用户说的话') 会自动解析出 function_calls（按用户提到的顺序，要两个就给两个），执行你的函数并回传结果。README 里的 get_weather 例子很典型：一句「what's it like in Lagos right now?」直接变成带 city 参数的调用。第二条是 Structured Extraction：你声明一个输出结构（shape），把脏文本丢进去，拿回带类型的字段——发票、预订信息、通知、表单都能抽，而且它说「extraction generalises to classification」，也就是加了 enum 就能直接当分类器用。第三条是 Text Embedding：同一个模型能返回句向量，让 App 在本地做语义搜索、匹配和路由，不用再为 embedding 单独拉一个模型。

技术上，它叫「Laddered Simple Attention Network」，几个关键词值得划重点。FFN 位置换成了 Monarch Hadamard MLP，注意力用 GQA 并配了 causal conv taps，还有一块 engram n-gram memory（靠 gather 读取，参数量的大头在这儿），再加上 multi-lane hyper-connections。最妙的设计是「Ladder」：训练时就让 2 层到 20 层的每一个深度都是可部署的完整模型——这相当于一次性训练出一整个「模型家族」，高端设备上跑 20 层，一个便宜的 MCU 上就跑 2 层，同一个权重文件、同一套接口，非常省事。解码侧则是从你的 schema 编译出的 byte-level grammar 硬约束每个 token，保证结构化输出一定能被 parse；同时有一个学习出来的 head 输出校准过的置信度。

部署这块是我觉得最像「工科生做事」的部分。整个模型是一个 8-29 MB 的二进制；每个平台目录里都预置了一个不到 1 MB 的引擎，启动时去 map 并原地读取 needle3.cact 权重（Cactus Quants 量化，2.125 bits/weight）。命令层面就是 pip install cactus-needle，然后 needle build --platform macos-arm64，或者 needle build --platform linux-arm64 --layers 8 --out ./pi 直接给树莓派编一个 8 层版本。支持 Mac、Linux ARM64、浏览器、WASI，还有 C API，甚至可以按官方文档自己写运行时（blog 里有 porting-needle 一篇专门讲怎么看 tensor order、prompt on the wire、ladder rule，还给了 oracle 测试）。

定制化也做得很周到。pip install "cactus-needle[train]" 之后，needle finetune data.jsonl --epochs 10 --out adapter.safetensors 在本地就能 4 bit 训练并导出，再用 needle build --lora adapter.safetensors --layers 8 --out tuned.cact 把 LoRA 合进指定深度的子网络。README 声称在 DroidCall 上微调能把每个子网络拉高 18 到 36 个点，4 层以上就能打过 DeepSeek V4 Flash。当然，这部分是官方自报数据，实际效果建议自己跑一遍 benchmark。
